# docs — 分析・設計ドキュメント

このフォルダは、AI支援型インフラ調査ツール **kyumei** の設計の土台となる分析・方法論ドキュメントを格納する。

## 出発点となったケーススタディ

- **元記事**: [Hacking Google with AI for $500,000](https://brutecat.com/articles/hacking-google-with-ai/) (Arvin Shivram / brutecat)
- **概要**: AI(Claude)を組み込んだファジングパイプラインで、約3,600個のAPIキーと約1,500個のGoogle APIを横断調査し、約3ヶ月で$500,000相当(25件以上)の脆弱性を発見した事例。
- **なぜ重要か**: 「広大でノイズの多い探索空間を、構造化された自動パイプラインに変換し、AIに意味的推論を、決定的ツールに広さ・検証・反ハルシネーションを担わせる」という、まさに kyumei が目指す設計の完成形だから。

## 読む順番

1. まず **01** で「実際に何が起きたか」を理解する。
2. **02** で「それは何の一般原理だったのか」を抽出する。
3. **03** で「我々のツールにどう実装するか」へ橋渡しする。

## 重要な前提(倫理・スコープ)

元記事は **Google の公式バグバウンティ(bugSWAT招待)という許可された枠組み** での研究である。kyumei も同様に、**自己資産・検証環境・明示的に許可されたPoC対象に限定**して使うことを前提に設計する。スコープ allowlist・レート制限・監査ログを中核機能として組み込む(詳細は 03)。
